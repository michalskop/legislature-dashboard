# DIVERGENCE.md — apps/cz-cities vs apps/cz-psp

`apps/cz-cities` was created as a **third copy** of `apps/cz-psp` (per plan.md decision D4 —
speed over dedup; the shared-package refactor is deliberately deferred to audit task **T6**). This
file is intended to become T6's work order: every file below that says "identical, copied as-is"
is a duplication candidate; every file that says "diverges" documents exactly what's app-specific
vs what's boilerplate that a shared package/template could absorb.

Generated by diffing `apps/cz-psp` against `apps/cz-cities` on 2026-08-04 (excluding `.next`,
`node_modules`, `*.tsbuildinfo`, `.turbo`). Re-run to check drift:

```
diff -rq apps/cz-psp apps/cz-cities -x '.next' -x 'node_modules' -x '*.tsbuildinfo' -x '.turbo'
```

## Summary

- **16 files identical, copied as-is** — pure boilerplate, zero app-specific content. Strong T6
  candidates (move to a shared package/template verbatim).
- **34 files diverge** — mostly small, mechanical differences (app id, translations, party
  colors/IDs, site URL) inside otherwise-identical structure. Also strong T6 candidates (the
  *shape* is shared, only config/content differs — exactly what a `ParliamentConfig`-driven
  shared component should already handle, and mostly does, except where noted below).
- **13 files added** (not present in cz-psp) — placeholder fixtures and one renamed/local module.
- **8 files removed** (present in cz-psp, deliberately not carried over) — PSP-specific
  infrastructure (the "Sněmovna Digest" video-summary microservice) that has no cz-cities
  equivalent.

## 4. Removed (8 files/dirs present in cz-psp, deliberately not carried over)

cz-psp additionally describes and links to a separately deployed **"Sněmovna Digest"** video/
event-summary microservice (reachable at `/digest`, proxied via `next.config.ts`'s
`DIGEST_ORIGIN` rewrite). No such service exists for cities — copying these files would have
published discovery metadata (MCP server card, API catalog, auth docs) for a subsystem that
doesn't exist in this app, which would be actively misleading to crawlers/agents, not just unused
boilerplate. Removed:

- `src/data/vote-events/86377.json`–`86381.json` — **also removed because they contain real PSP
  MP names and real vote records** (200 real voters per file); replaced with generic
  `placeholder-*.json` fixtures using the same 8 fictional councillors as the analysis fixtures
- `next.config.ts`'s `/digest/*` rewrite and `DIGEST_ORIGIN` env var
- `public/.well-known/mcp/server-card.json` — MCP server card for "Sněmovna Digest"
- `public/.well-known/api-catalog` — RFC 9727 API catalog, references digest endpoints
- `public/.well-known/agent-skills/czech-chamber-dashboard/`,
  `czech-chamber-datasets/` — renamed to `city-assembly-*` (see Added), not literally removed,
  but the old PSP-named dirs don't exist in cz-cities

## Placeholder data decision (build-time fetching)

`apps/cz-psp`'s `src/lib/data.ts` fetches real, committed analysis output JSON from
`raw.githubusercontent.com/michalskop/cz-psp-data-2025-202x` at build/request time. No equivalent
exists for cities yet — the data pipeline (plan.md tasks C1/C7/C8, `cz-municipalities-votes-2022-2026`
restructure) is being built in parallel and hasn't published anything under
`<city>/analyses/*/outputs/*.json`.

**Decision: `fetchJson()` reads small, clearly-labeled placeholder fixtures from local disk
(`src/fixtures/analyses/`) instead of fetching a URL.** Rejected alternatives and why:

- **Fetch the real future URL anyway** (`raw.githubusercontent.com/.../cz-municipalities-votes-2022-2026/main/<city>/analyses/...`) —
  would 404 today (nothing published yet). `next build` runs data-fetching code at build time for
  static/ISR pages, so this would break `pnpm build` outright, or make every build silently
  depend on GitHub's availability for data that doesn't exist. Rejected.
- **Point at a fake/mocked external HTTP endpoint** — adds infrastructure (a mock server) for no
  benefit over reading a committed file directly; also less obviously "this is fake data" to a
  future reader than a `src/fixtures/` directory.
- **Local fixture read (chosen)** — deterministic, works offline, and is a direct extension of a
  pattern cz-psp *already uses* for `src/data/vote-events/*.json` (loaded via
  `readFile(join(process.cwd(), "src/data/vote-events", ...))` in the vote-event detail page) —
  not a new technique, just applied one layer up to the analysis-outputs fetcher too. Cost: no ISR
  revalidation for this data (irrelevant — fixture data never changes) and one clearly-documented
  swap-back point once real data exists.

`parliamentConfig.dataBase` still documents the *future* real URL shape (per plan.md section 2 /
D8's URL pattern), so switching back to a real `fetch()` call is a small, obvious change in one
function (`fetchJson` in `src/lib/data.ts`, and the equivalent in
`scripts/generate-ai-readability.mjs`) once a city's analysis outputs are actually published —
not a redesign.

## Notes for T6 (future de-duplication refactor)

- Three copies now confirmed duplicating **identically** (16 files, section 1) — highest-value,
  lowest-risk T6 targets.
- `@legislature/ui`'s `PartyBadge`/`PartyFace`/`SortableMpTable` hardcode `CZ_PSP_PARTY_*` and
  `SK_NRSR_PARTY_*` dictionaries by name inside the "shared" package (`packages/ui/src/components/
  PartyBadge.tsx`, re-exported via `packages/ui/src/index.ts` and used directly in
  `packages/ui/src/components/SortableMpTable.tsx` and `packages/charts`'s consumers). This means
  the shared package is *not actually* app-agnostic today — adding a third city broke the
  pattern (worked around locally in this app via `src/lib/parties.ts`, see section 3). T6 should
  make party color/label metadata a `ParliamentConfig`-supplied lookup instead of a hardcoded
  per-parliament export.
- The `/region`, `/regions` routes are dead weight for any config without a `constituency`
  organization (sk-nrsr and cz-cities both ship them unused). T6 (or A2) should decide whether
  `regionDetail`/region routes become conditional on `organizations` containing a `constituency`
  entry, rather than always-present-but-empty.
- `src/lib/lang.ts`'s cookie-based `getLang()` is flagged by the existing audit (T8) as forcing
  dynamic rendering via `cookies()`. It's unchanged here (identical copy) — A2 replaces it with
  path-prefix i18n per plan.md D5, at which point this file stops being a T6 dedup candidate and
  becomes obsolete in all three apps.
